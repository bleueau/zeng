# Mikey Framework 推理流程

> **用途：** 当面对一个具体的聊天/关系/约会案例时，按此流程逐步分析。
> **约束：** 每一步均需引用对应的Concept和Evidence。不可跳过步骤。不可在没有Evidence支持的情况下做出推论。

---

## 流程总览

```
用户案例描述
    │
    ▼
Step 1: 识别关系阶段
    │
    ▼
Step 2: 提取核心变量
    │
    ▼
Step 3: 分类问题类型
    │
    ▼
Step 4: 匹配对应原则
    │
    ▼
Step 5: 调用决策模型
    │
    ▼
Step 6: 输出分析结果
```

---

## Step 1：识别关系阶段

### 目的

判断当前互动处于哪个阶段，因为不同阶段的适用规则不同。Mikey体系明确禁止越级操作（E0093：根据关系阶段做对应的事，不能越级操作）。

### 阶段定义（基于Evidence）

| 阶段 | 特征描述 | 核心任务 | 来源Concept |
|------|----------|----------|-------------|
| **陌生阶段** | 未建立联系或刚交换联系方式。对方有戒备心和边界感是正常的。 | 破冰、传递正面感觉、建立安全感 | C003(搭讪与开场) |
| **熟悉阶段** | 有过初步互动，双方知道彼此是正常人。但尚未建立吸引。 | 传递人设、建立吸引、适时邀约 | C003, C001 |
| **暧昧阶段** | 已有明显吸引信号（IOI），互动进入升温状态。 | 共振、试探窗口、把握升级时机 | C001(约会与升级) |
| **亲密阶段** | 已发生亲密关系。 | 维持框架、控制需求感、避免一致性断裂 | C001, C015, C017 |
| **长期关系阶段** | 确定关系后持续相处。 | 一致性维持、吸引力保鲜、边界感 | C015(长期关系与策略) |

### 识别问题

- Mikey体系认为：很多兄弟捕捉不到社交动态，女性上钩了也不知道，因此不敢及时约会（E0517, E0661）
- Mikey体系认为：女生回复态度很好但从不主动发消息/提供话题，说明没有窗口，是在吊着你（E0378）

### 判据

使用以下问题判断阶段：

1. 双方是否已经建立联系？（否→陌生阶段）
2. 对方是否主动发起过互动或提供话题？（否→可能仍处于熟悉阶段早期）
3. 对方是否表现出明显兴趣信号（IOI）？（否→熟悉阶段；是→暧昧阶段）
4. 是否已发生亲密接触？（是→亲密阶段或长期关系阶段）
5. 是否已确定关系并持续相处超过一个月？（是→长期关系阶段）

**相关Evidence：** E0056, E0070, E0072, E0093, E0173, E0517, E0661, E0378

## Step 2：提取核心变量

### 目的

从案例描述中提取Mikey体系中反复出现的核心分析变量。

### 变量清单（基于Evidence）

#### V1：吸引力水平

判断当前是否存在吸引。这是Mikey体系中最基础的变量。

- **有吸引的信号：** 对方主动发起互动、提供话题、接受邀约、眼神接触舒适、身体语言开放
- **无吸引的信号：** 对方只被动回复不主动、拒绝/推脱邀约、不提供注意力
- **相关Evidence：** E0006, E0301, E0302, E0316, E0322, E0383, E0485, E0521

#### V2：需求感程度

判断自己（或案例中男方）是否正在暴露过度的需求感。

- **需求感高的信号：** 快速回复消息、频繁主动发起互动、追逐对方反应、对方不回应时产生焦虑、聊天热度远高于对方
- **相关Evidence：** E0194, E0520, E0534, E0509, E0250, E0542

#### V3：框架位置

判断当前关系中谁处于上位（框架更强的一方）。

- **上位信号：** 可以自然地表达不同意见、拒绝不合理要求时对方不会反弹、对方主动找话题缓解冷场
- **下位信号：** 迎合对方、害怕表达不同意见、被对方节奏带着走、情绪随对方反应剧烈波动
- **相关Evidence：** E0016, E0234, E0045, E0231, E0075

#### V4：投资差距

判断双方在关系中的情绪/时间/注意力投入比例。

- **对方投入高的信号：** 主动发起互动、主动分享个人信息、主动邀请、为你调整时间
- **对方投入低的信号：** 回复敷衍、不主动发起互动、推脱邀约、不提供话题
- **相关Evidence：** E0029, E0036, E0356, E0393, E0703, E0740

#### V5：窗口状态

判断当前是否存在升级关系的窗口（好感度达到可升级程度）。

- **有窗口的信号：** 对方愿意单独相处、身体语言开放、接受肢体接触试探、主动制造接触机会
- **无窗口的信号：** 保持距离、拒绝/回避肢体接触、回复变冷
- **相关Evidence：** E0003, E0005, E0059, E0309, E0517, E0661, E0662

#### V6：一致性状态

判断当前行为是否与之前传递的人设/行为线索一致。

- **一致：** 前后行为逻辑自洽，人设没有断裂
- **不一致：** 前后行为矛盾（如前期展现强框架→后期开始讨好；前期自然风趣→后期紧张拘束）
- **相关Evidence：** E0027, E0175, E0273, E0274, E0374, E0376, E0462, E0727

### 输出格式

完成Step 2后，应输出一个变量评估表：

```
| 变量 | 评估 | 关键信号 | Evidence |
|------|------|----------|----------|
| 吸引力水平 | 低/中/高 | ... | E0xxx |
| 需求感程度 | 低/中/高 | ... | E0xxx |
| 框架位置 | 上位/平衡/下位 | ... | E0xxx |
| 投资差距 | 对方多/平衡/你多 | ... | E0xxx |
| 窗口状态 | 有/无/不明 | ... | E0xxx |
| 一致性状态 | 一致/断裂 | ... | E0xxx |
```

## Step 3：分类问题类型

### 目的

将案例的核心问题归类到已知问题类型。

### 问题类型（基于Concept Map和Evidence）

| 类型 | 典型表现 | 关键Concept |
|------|----------|-------------|
| **搭讪-无回应型** | 加了微信后对方不回复或敷衍 | C003, C007 |
| **聊天-降温型** | 聊天从热到冷，对方越来越不投入 | C017, C002, C007 |
| **邀约-被推脱型** | 每次邀约都被用忙/有事推脱 | C001, C007, C004 |
| **约会-升级失败型** | 约会后对方变冷，或约会中升级被拒绝 | C001, C004 |
| **关系-框架沦陷型** | 从原本的上位变为下位，开始被对方主导 | C004, C005, C012 |
| **长期-吸引力流失型** | 确定关系/发生关系后吸引力下降 | C015, C009, C017 |
| **心态-焦虑/内耗型** | 对方不回复时产生严重焦虑，无法正常生活 | C002, C006 |
| **边界-被试探型** | 对方不断提出越界要求，你感到不舒服 | C012, C005, C007 |

### 分类方法

1. 阅读案例描述，提取核心症结
2. 对照上表找到最匹配的类型
3. 如果没有完全匹配的类型，选择最接近的，并标注差异

## Step 4：匹配对应原则

### 目的

根据Step 2的变量和Step 3的问题类型，调用principles.md中的核心原则。

### 匹配规则

| 问题类型 | 优先调用原则 | 次要调用原则 |
|----------|-------------|-------------|
| 搭讪-无回应型 | P02(潜沟通), P10(吸引先于技术) | P09(零压力状态) |
| 聊天-降温型 | P03(需求感), P10(吸引先于技术) | P06(投资差距), P04(一致性) |
| 邀约-被推脱型 | P10(吸引先于技术), P01(关系动态) | P03(需求感), P06(投资差距) |
| 约会-升级失败型 | P05(施压与减压), P10(吸引先于技术) | P01(关系动态), P09(零压力状态) |
| 关系-框架沦陷型 | P01(关系动态), P08(边界感) | P07(自我价值感), P06(投资差距) |
| 长期-吸引力流失型 | P04(一致性), P03(需求感) | P07(自我价值感), P01(关系动态) |
| 心态-焦虑/内耗型 | P07(自我价值感), P09(零压力状态) | P06(投资差距) |
| 边界-被试探型 | P08(边界感), P01(关系动态) | P05(施压与减压) |

### 输出

列出调用的原则及其在本案例中的具体适用方式（不是照抄原则原文，而是应用到具体情境）。

---

## Step 5：调用决策模型

### 目的

根据Step 2的变量调用decision_models.md中的结构化判断模型，获得「如果A则B」式的具体判断。

### 调用方法

1. 根据问题类型选择决策模型
2. 输入Step 2中的变量值
3. 输出判断结果

详细决策模型见 [decision_models.md](decision_models.md)。

---

## Step 6：输出分析结果

### 输出结构

```
## 案例分析：[简述]

### 1. 当前阶段
[阶段名称 + 判断依据 + Evidence引用]

### 2. 变量评估
[六变量表]

### 3. 问题类型
[类型名称 + 原因]

### 4. 核心症结
[用1-3句话说明根本问题]

### 5. 调用原则
[列出原则 + 在本案例中的适用方式]

### 6. 决策判断
[调用的决策模型名称 + 判断结果]

### 7. 建议方向
[基于以上分析的行动方向，格式为"Mikey体系认为..."而非"你应该..."]
```

### 注意事项

- 所有结论必须可追溯到Evidence
- 不输出没有Evidence支持的推论
- 如果案例信息不足以判断某个变量，标注「信息不足」而非推测
- 不要输出绝对化结论（如「女生一定会...」）
- 使用「Mikey体系认为...」而非「事实是...」的表达方式
