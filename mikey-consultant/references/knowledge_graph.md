## 1. 设计理念

### 1.1 为什么需要 Knowledge Graph

Phase 0 审计报告指出 AI 的核心问题之一：**抓单个 Evidence**——看到"回复慢"就直接用 P03（需求感），但忽略了可能同时存在的窗口问题、框架问题、一致性问题。

Gate 3（理论覆盖检查）需要一张"理论关系图"来回答：**给定一个维度（如"需求感"），与之关联的所有理论、模型、Pattern 是什么？如果我只用了其中一个，我遗漏了什么？**

### 1.2 这不是什么

- **不是数据库**——不需要 query engine
- **不是 Neo4j**——不需要图数据库
- **不是知识本体**——不需要 formal ontology
- **是**——一张 Markdown + JSON 的关系表，让 Gate 3 快速查阅

## 3. 边类型定义

| 边类型 | 符号 | 含义 | 示例 |
|--------|------|------|------|
| **支撑** | `→` | A 的因果链支撑 B 的存在/判断 | M2 → P03（需求感传导模型支撑"需求感是吸引力杀手"原则） |
| **矛盾** | `↔` | A 与 B 在特定条件下给出相反方向 | E0528 ↔ E0502（"没有安全感是好事" vs "邀约前提是安全感"——不同维度） |
| **互补** | `+` | A 和 B 共同使用才完整 | P03 + P06（需求感 + 投资差距共同解释单向追逐的破坏） |
| **前置** | `≺` | A 是 B 的前提条件 | M1 ≺ M5（吸引力是窗口的前提） |
| **后置** | `≻` | A 是 B 的下游结果 | M8 ≻ M1（关系衰减最终导致吸引力归零） |
| **替代** | `∥` | A 和 B 解决同一类问题但路径不同 | DM01 ∥ DM06（窗口判断和邀约时机判断都是"能否推进"类判断） |
| **实例化** | `::` | Pattern 是 Mental Model 的具体场景实例 | E02 :: M2（聊天降温是需求感传导的具体实例） |
| **调用** | `@` | Gate 调用某个理论/模型 | G1 @ P3（Gate 1 调用 Pattern Recognition 能力） |

### 4.1 因果变量关系图（V 层）

```
         V1 吸引力
        ↗ ↑ ↖
     ≺  |  |  ≻
    /   |  |   \
V5 窗口  |  |   V6 一致性
  ↑     |  |     ↓
  |    V2 需求感  |
  |   ↗  ↑  ↖   |
  |  /   |   \  |
  | /    |    \ |
V4 投资 ←→ V3 框架
```

**关键边：**
- V2 → V1：需求感暴露杀吸引力（负因果，M2 核心链）
- V3 → V1：框架位置影响吸引力（M3→M1）
- V4 → V1：投资差距创造或破坏吸引（M4 双向）
- V5 ≺ V1：吸引力是窗口的前提（M1≺M5）
- V6 → V1：一致性维持吸引力（M6→M1）
- V2 ↔ V3：需求感暴露 ↔ 框架沦陷（互为因果，M2↔M3）
- V2 ↔ V4：需求感暴露 = 单向投资加剧（M2↔M4）
- V3 ↔ V4：框架位置和投资方向同向（M3↔M4）
- V2 → V5：需求感暴露加速窗口关闭（M2→M5）
- V6 → V3：一致性断裂→测试加剧→框架沦陷（M6→M3）

## 7. 使用指南

### 7.1 Gate 3 如何使用

Gate 3（理论覆盖检查）执行时：

1. **确定已识别的维度**——从 Gate 1 模式匹配和 Gate 2 根因定位中，哪些维度已被评估？
2. **查覆盖矩阵**——对每个维度，查看关联的 Principle / DM / Pattern 是否都已考虑
3. **检查遗漏**——有没有相关维度被跳过？特别是 V2（需求感）作为杀手变量，必须检查
4. **检查矛盾**——如果判断涉及矛盾节点对，确认适用条件是否正确

### 7.2 Gate 2 如何使用

Gate 2（根因定位）执行时：

1. **查因果链**——从症状出发，沿 Mental Model 的因果链追溯根因
2. **查杀手变量**——V2 是否在起作用？如果是，它同时影响了哪些维度？
3. **查前置条件**——根因是否因为某个前置条件缺失？（如：吸引不存在是因为窗口从未打开）

### 7.3 防止"抓单个 Evidence"的机制

当 AI 倾向于只引用一条 Evidence 时：

1. **查覆盖矩阵**——这条 Evidence 属于哪个维度？其他 5 个维度是否也被检查了？
2. **查关联 Pattern**——这条 Evidence 是否属于某个 Pattern？该 Pattern 的易混淆模式是否被排除了？
3. **查矛盾节点**——是否存在适用条件不同的矛盾对？当前案例适用哪个？

---

## 总结

### 一句话

**Knowledge Graph 是 Gate 3 的查询表——给定一个维度，它告诉你所有关联的理论、模型和 Pattern，确保你不会只看一个角度就下结论。**

### 核心价值

| 没有知识图谱 | 有知识图谱 |
|------------|----------|
| 看到"回复慢"→只用P03 | 看到"回复慢"→查V2覆盖矩阵→同时检查V1/V3/V4/V5 |
| 抓单条Evidence | 查关联Pattern→确认是E02还是M01→排除易混淆模式 |
| 遗漏理论维度 | 六维强制覆盖→杀手变量V2必查 |
| 忽略矛盾 | 查矛盾节点对→确认适用条件 |
